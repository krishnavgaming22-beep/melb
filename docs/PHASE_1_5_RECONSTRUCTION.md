# MELB. Phase 1.5 — real geography and architectural map

Phase 2 now extends this foundation: see [PHASE_2_DISCOVERY.md](PHASE_2_DISCOVERY.md) for the twelve-landmark interface, revised transition timing, research, tests and pending live browser verification. The descriptions below record the Phase 1.5 baseline.

Implemented in the existing homepage on 12 October 2026. The prior arrival aircraft, Australian map, typography and single-canvas/ScrollTrigger architecture remain. The active city model is now `public/assets/models/melb-city-phase15.glb`. Earlier schematic and photogrammetry assets are retained but neither is imported by the main city component.

## Investigation

The preceding model was generated by `scripts/build_city.py` from a small schematic street layout and repeated/randomly placed boxes. It had 9,240 triangles and no real building-footprint dataset. The recording supplied on 12 October was sampled at 12 points across its 12.763-second duration; selected frames confirm sparse geometry and low contrast. Strong ambient, fill and key light combined with pale materials washed out its forms.

The official 2023 City of Melbourne building-footprint dataset was identified, but the browser's saved permissions rejected DataVic. Localhost browser inspection was also rejected by the browser URL policy. No alternate browser, raw browser automation or blocked-dataset download was used to bypass either restriction.

The permitted alternative was OpenStreetMap via Overpass. Its homepage was accessible through Computer Use. A read-only geographic extract was fetched using the documented API with an application user-agent and JSON accept header; the first default-header request returned HTTP 406 and was retried after the documented cooldown. The successful extract is cached locally and the website makes **no runtime Overpass requests**.

## Data and licensing

- Source: [Overpass API](https://wiki.openstreetmap.org/wiki/Overpass_API), OpenStreetMap snapshot `2026-10-12T07:44:35Z`.
- Source CRS: WGS84 longitude/latitude. Bounds: west 144.935°, south −37.8375°, east 144.999°, north −37.7975°.
- Presentation: one documented local equirectangular projection centred at 144.967°, −37.8175°, with 120 metres per scene unit. This is an architectural map, not a survey or a datum conversion from the preserved MGA55 photomesh.
- Licence: [ODbL 1.0](https://opendatacommons.org/licenses/odbl/1-0/), with [OpenStreetMap attribution guidance](https://osmfoundation.org/wiki/Attribution_Guidelines). The homepage displays © OpenStreetMap contributors and a data/credits link.
- Downloadable source-derived database and per-building height method: `/assets/data/melbourne-osm.geojson.gz`. Metadata: `/assets/data/melbourne-data.json`. This preserves the geographic features, source identifiers and derived height attributes under ODbL. Rendering code and original styling are separate from the geographic database.

Raw source: `assets/geography/phase15/osm-source.json`; reproducible query: `scripts/phase15.overpass`; pipeline: `scripts/build-phase15-city.mjs`.

These are feature counts, not a claim of 22,768 unique surveyed buildings. Community height tags are not independently validated measurements. Missing height uses floor count × estimated 3.2 m; otherwise a recorded building-type estimate is used (default 8 m). There is no random height/footprint generation. Details are recorded in `height-audit.json` and the downloadable derived database.

Actual footprint rings and holes are extruded; overlapping parent roofs are cut beneath taller mapped building parts. This preserves Eureka's different-height components and the MCG's individually mapped stands. Eight tagged pyramidal roofs receive a roof rise from `roof:height` or an explicitly estimated rise. Other roof styles currently use flat caps plus the mapped building-part structure; this is not intricate roof reconstruction.

Water polygons and parks are unioned and clipped to the same boundary. Roads, paths and railways use their mapped alignments, with width from source width/lanes where present and class estimates otherwise. Bridge tags separate surface layers; bridge deck elevation is a presentation estimate. Terrain is flat: no elevation dataset or AHD heights were integrated.

## Experience and interaction

The existing city section is refactored rather than duplicated. `cityTransition.ts` defines the shared scroll state: first an oblique overview; camera rise at 25–75% of the city phase; height compression at 50–75%; then fully overhead exploration. Buildings and footprints retain identical X/Z coordinates. Quantised glTF node scales/translations are preserved during the height morph. Materials progressively lose shading and shadows soften before disabling.

Lighting drops from the aircraft's bright sky rig to a restrained city rig. Buildings use pale stone/warm white, water dusty blue, parkland sage and highlights muted copper. The flat-map shader darkens building footprints for legibility. Cursor parallax is damped. No image/map swap or second canvas is used.

The shared location registry contains all 12 requested destinations with OSM feature references and future route/model fields. The initial eight interactive pins are MCG, Flinders Street, Federation Square, Shrine, Botanic Gardens, Queen Victoria Market, Marvel Stadium and State Library. Positions derive from the selected source geometry bounds centres; these are label anchors, not surveyed entrances. Eureka, Rod Laver, Royal Exhibition Building and Arts Centre are also registered and their mapped geometry is included.

Desktop: drag the map, use +/− or Ctrl/⌘-wheel to zoom, and Reset view. Ordinary wheel scrolling continues the page journey. Focus the map for arrow-key panning, +/− zoom and Home reset. Mobile: Move map enables touch pan/pinch; Resume scroll returns one-finger scrolling. Selection previews remain lightweight; detailed landmark experiences are deferred. Pan/zoom offsets fade out when reversing into the cinematic sequence, without altering model coordinates.

## Optimisation and verification

The city is batched by material and approximately 960 m spatial cells, compressed with Meshopt and 16-bit position quantisation, and frustum-culled. There are no facade textures. Desktop DPR remains capped at 1.5, mobile at 1.25. Mobile/reduced-motion/low-power mode disables city mesh shadows. Geometry has one cached asset and route-owned materials are disposed during cleanup.

`node --experimental-strip-types scripts/verify-city-map.mjs` decoded the actual production GLB and checked all 1,287,611 stored vertices for finite coordinates, valid heights, and zero horizontal drift under the implemented quantisation-aware height transform. It checks required geographic layers, 12 registry entries, eight pins, desktop/mobile overhead framing, stage endpoints and bounded pan/zoom/reset. Result: pass. Node file-read plus decoding measured 77 ms in that run; this is **not** a browser/network/GPU load-time measurement.

The TypeScript/Vite production build passes with the existing large Three.js bundle warning. Blender overview and overhead inspection renders show the real Hoddle Grid, Yarra, Docklands, parks, dense skyline and stadium precincts. The Blender script reads a derivative GLB, preserving original downloaded photomesh folders.

**Browser validation remains blocked.** Browser FPS, console/shader compilation, scroll reversal appearance, responsive DOM overlap and mouse/touch interaction have not been verified live. No FPS figure is claimed. Blender renders are geometry/style checks, not website screenshots. The implementation is integrated and the local server is running, but browser visual acceptance is outstanding.
